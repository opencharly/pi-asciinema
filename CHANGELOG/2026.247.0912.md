# 2026.247.0912 — feat: cast_read - asciinema .cast reader pi extension

## Summary

New pi agent package **`pi-asciinema`** in the opencharly org: a pi extension registering the custom tool **`cast_read`**, which lets any agent directly read and analyze asciinema `.cast` terminal recordings (asciicast v1/v2/v3 — the format produced by asciinema and by Charly's `record:` check verb).

- **`cast_read`** returns bounded structured analysis: `summary` (terminal size, duration, event counts, markers, first/last output), `events` (filtered), `text` (ANSI-stripped transcript with markers inline, paged via offset/limit, timing prefixes). Output hard-capped by `max_chars` (default 40000) with truncation note — never floods agent context.
- **Zero runtime deps**: self-contained parser (v1/v2/v3; timing semantics per asciinema-player reference — v1/v3 deltas accumulate, v2 absolute; tolerant of malformed lines, `x` string-or-object payloads, unknown header keys).
- **Consumption**: the org's main pi config lives in the umbrella `.pi/settings.json` (follow-up umbrella PR pins `git:github.com/opencharly/pi-asciinema@<tag>`); from the umbrella root, **bare `pi -p "..."` works with zero extra parameters** (verified live).
- CI: `ci.yml` (typecheck + L1/L2 tests + no-LLM load check), `validate-pi-p.yml` (full L3 `pi -p` matrix with json-mode observability, secret-gated), `release.yml` (tag-triggered GitHub Release), plus the org-wide pr-validator and tag-on-merge dispatchers.
