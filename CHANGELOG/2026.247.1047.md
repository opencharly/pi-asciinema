# 2026.247.1047 — ci(validation): pre-warm pi before the L3 pi -p matrix

## Summary

Validation-harness fix discovered while running the umbrella worktree validation: the **first** pi spawn in a fresh checkout absorbs lazy package installs (git package clones, vendored mirrors, npm installs) and can exceed the per-case timeout. Adds one cheap warmup `pi -p` call before the L3 matrix in both harnesses, and hardens the invocation/assertion forms per the first review round:

- `scripts/validate-bare.mjs` — warmup + fact-token assertions
- `scripts/validate-pi-p.mjs` — warmup, canonical `-p "<prompt>"` order, warmup cwd honored

## Response to review findings

1. **`-p` flag placement:** the mechanism in the finding (that `-p` consumes `--no-session` as the prompt) does not hold for this pi version — verified directly in pi's own CLI parser (`dist/bundle/chunks/chunk-OMWWHBTG.js`): `-p`/`--print` sets `print=true`, and only consumes the NEXT arg as the prompt when it is not `@…` and does not start with `-` (unless `---`). The matrices above (with real fixture tokens asserted in stdout) are empirical proof the prompt landed. The invocation is nonetheless now written in the canonical documented form `-p "<prompt>"`, which is unambiguous under every parser reading.
